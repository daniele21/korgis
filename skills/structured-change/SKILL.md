# Structured Change
State **observable outcome, canonical owner, invariants and proof**. Inspect material consumers/fakes/tests; establish failing evidence for reproducible bugs when practical. Extend existing owners rather than adding duplicate runtime/policy state. Preserve resource bounds/cancellation/cleanup, local-first/privacy, public capability semantics and evidence identity. Product UI changes use `design-product-experience`. Use `validate-change` while iterating; `preflight-change` owns integration/release readiness.
